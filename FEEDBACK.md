# Feedback — on these instructions, not on your work

**This file is about us, not you.** Nothing in it is scored. Say the blunt
thing.

You are the first three people to use any of this. Where it is confusing,
wrong, or missing, that is a defect in our instructions — and the only way we
find out is if you write it down while it is annoying you. A week later you
will have forgotten, or worse, you will have decided it was your fault.

Fill it in **as it happens.** Two minutes, in the moment, beats an hour at the
end. Push it with everything else.

---

## 1 · What didn't make sense

One row each time something stopped you, confused you, or turned out to be
wrong. "I couldn't tell whether X meant Y" is a perfect entry.

| Date | Where | What didn't make sense | How I'd fix it |
|---|---|---|---|
| | | | |

**Where** = the file or the moment — `README.md`, `BRIEF.md`, `CLAUDE.md`,
`/team-onboarding`, the PRD gate, a template file, or "nowhere, I just didn't
know what to do next."

**How I'd fix it** is the valuable column. A guess is fine. "Say it in one
sentence at the top instead of three paragraphs later" is a real answer.

### Things worth recording, if they happen

- An instruction you had to read twice
- Two documents that said different things
- A word we used as if you already knew it
- Something you looked for and could not find
- A step that assumed a tool or an account you did not have
- A moment you nearly gave up, and what you did instead

That last one matters more than the rest. Write it down even if you pushed
through.

`/team-onboarding`, anything from a plugin or marketplace, and anything you
wrote yourself.

| Skill | What I used it for | Did it help? | Notes |
|---|---|---|---|
| | | | |

**Did it help?** — *yes* / *no* / *partly*. "No" is the useful answer and it
costs you nothing.

If you built a skill of your own during this, say so here. That is a strong
signal, not a deviation.

If you used no skills at all, write that. It is a finding.
